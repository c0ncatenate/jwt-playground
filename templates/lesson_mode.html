Guided lesson – JWT journey

Follow these steps in order if you are using this playground to teach JWTs in a workshop or to explore them on your own.

  1. Start with a happy-path token – open Scenario 1 – Signed JWT flow and issue a token for a test user. Point out the header and claims.
  2. Try to cheat by editing JSON – open Scenario 2 – Tampering with claims and change role from user to admin. Compare the result when you re-sign vs when you send a forged token.
  3. Play with time – open Scenario 3 – Expired tokens and experiment with iat, exp, and clock skew.
  4. Showcase bad practices – visit Scenario 4 – Bad practices and talk through why weak secrets and skipping verification are dangerous.
  5. Scope tokens to services – use Scenario 5 – Audience and issuer checks to show how aud and iss prevent token reuse across services.

Discussion prompts

  • Where should JWTs be stored on the client side in a real app?
  • How short can token lifetimes be without hurting UX?
  • What is your strategy for key rotation and revocation?
  • Which claims do you rely on for authorisation vs identification?

Production checklist

  • Use strong secrets or asymmetric keys; never check tokens with alg=none.
  • Pin allowed algorithms on the server instead of trusting the header.
  • Use short-lived access tokens and, if needed, refresh tokens.
  • Validate iss, aud, and lifetimes on every request that uses a token.
  • Have a plan for rotating keys and invalidating tokens early when needed.
